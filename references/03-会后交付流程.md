# 03 · 会后交付流程

散会后，从「一堆转写文本」到「能发给别人的交付文档」，走四步 + 两步组装。

前置条件：`议程配置.json` 已填好（议题边界、讲者、交付文件名）。
**没有议程也可以跑**：`sessions` 为空时自动进入单场模式，全篇只有 `T1` / `S1` 一个议题，其余步骤一模一样。

---

## 第 1 步：合并（merge_transcripts.py）

把当天**多轮转写**合并成一份时间有序、去重的全文，并按议题切出 `_topics\T*.txt`。

```
<python> merge_transcripts.py
```

- 输入：`transcript_archive_glob` 匹配到的归档（`live_transcript_*.txt`）+ `live_transcript.txt`
- 去重算法：只在**时间窗内**（默认 10 秒）比对，命中「最长公共子串 ≥ 40 字符」或「相似度 ≥ 0.62」判为重录，
  保留信息量更大的那条（避免把讲者"重复强调"误杀）
- 输出：`全文转写-合并去重.txt`、`_topics\T*.txt`、`全文转写-未归入议题.txt`
- 可调：`--window 10 --lcs 40 --ratio 0.62`

> 归档文件命名 = **该轮采集的开始时间**，可据此定位任意时段的原文。

## 第 2 步：全局去重（dedup_global.py）

多轮采集会把同一段音频重复转写，且时间戳可能相差数分钟到数十分钟 —— 第 1 步的时间窗抓不到。

```
<python> dedup_global.py
```

- 算法：全量无序比对（5-token shingle 必须有交集 + ratio ≥ 0.62），**长句优先保留**
- 输出：`全文转写-最终.txt`，并打印「条/分钟」密度报告
- **看密度报告找漏录**：某段时间密度异常为 0，说明那会儿没录上或全是静音幻觉

## 第 3 步：按议题切片（split_topics.py）

用于**人工精修过 `全文转写-最终.txt` 之后**重新切一遍，并带一层短噪声行过滤。

```
<python> split_topics.py
```

输出同上，覆盖 `_topics\T*.txt`。

## 第 4 步：逐议题产出 Summary 与 Record

这一步**由 AI 完成，没有脚本**。对每个议题 `T*.txt`：

1. 写在 `_summary\S<n>.md` —— **Meeting Summary**（1 页速读，中英对照）
   建议结构：`## 背景与目的` / `## 核心观点` / `## 关键数据` / `## 结论与建议` / `## 存疑`
2. 写在 `_record\T<n>.md` —— **实时文字记录**，小节标题固定为 `## 一、实时文字记录`，
   逐条中英对照，保留时间戳，形如：

   ```markdown
   [10:23:45] EN: ...原文...
   中：...译文...
   ```

   > `## 一、实时文字记录` 这个标题**不要改**：`build_delivery.py` 靠正则识别它，
   > 会把它规范成 `## 实时文字记录 · Bilingual Live Transcript`。

3. 存疑处用 `[转写模糊]` / `[待确认]` / `[数字存疑]`，**不猜**。

## 第 5 步：装配主交付（build_delivery.py）

```
<python> build_delivery.py
```

- 读 `_summary\S*.md` + `_record\T*.md`，按 `议程配置.json` 的顺序拼成
  `会后交付-*.md` 与 `会后交付-*.html`
- HTML 是**独立可离线可打印**的单文件（内嵌 markdown 渲染器，自动生成目录表格、返回顶部按钮）
- 脚本会做**表格串列校验**（单元格里出现裸 `|` 会把表格撑坏）并列出缺失材料

## 第 6 步（可选）：合成 Word

把各议题 Summary 合成一份带封面 + 目录的 Word，适合发给客户/上级。
实战版本为 `_build_topic_summary_docx.py`（Daily 目录内），要点：

- 封面 + 目录 + 每议题另起一页
- 中英对照排版
- 生成后**必须打开确认**（页数、目录、分页对不对）

---

## 归档：按天分目录

一天一场会，建议一场一个目录。参考实战的目录约定：

```
<总目录>\
  Day1-YYYY-MM-DD\      ← 当天全部数据 + 交付
    会后交付-*.md/.html          主交付
    议题摘要-*.docx               Word 版
    _summary\S*.md  _record\T*.md  _topics\T*.txt
    会议摘要-双语.md / 会议看板.html        会中快照
    全文转写-*.txt               全量转写
    live_transcript_*.txt / recording_*.wav  原始素材
    议程-*.md  术语表-*.txt  _note_state-*.json
  根目录\                ← 只放「装置」：脚本 / 启动器 / 模型 / 说明
```

> ⚠️ 归档脚本（`_归档分天.py` 实战版）里的文件清单是**硬编码**的。
> 换会议请自己列清单，别直接套用 —— 存量 1 GB 级 wav 大量搬动前先确认目标盘空间。

---

## 交付物清单（一次会应该产出的东西）

| 产出 | 用途 |
|---|---|
| `会议看板.html` | 会中实时看；散会后是当天快照 |
| `会议摘要-双语.md` | 会中累积摘要（源文件） |
| `全文转写-最终.txt` | 全量、去重、时间有序的原始底稿 |
| `_topics\T*.txt` | 按议题切好的素材 |
| `_summary\S*.md` | 每议题 1 页 Meeting Summary |
| `_record\T*.md` | 每议题实时文字记录（中英对照） |
| `会后交付-*.md / .html` | ⭐ 最终交付（人看这个） |
| `议题摘要-*.docx` | ⭐ 对外发的 Word |
| `recording_*.wav` | 音频存档（可离线重跑） |
