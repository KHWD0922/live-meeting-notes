# 04 · 排障与实战经验

全部来自连续四天真实会议（一场行业科技论坛 + 一场客户峰会）的踩坑记录。
**遇到问题先看这一页。**

---

## A. 转写质量

### A1. 识别不准

按收益排序依次排查：

1. **拾音**（收益最大）：坐前排、麦克风正对讲台、垫软物、避开风噪
2. **术语表**：人名/公司名/缩写写进 `术语表.txt`。实测 `Kubernetes` → 不加表转成 `Cooper Netes`，加表就对了
3. **换大模型**：`--model medium`（更准、更吃 CPU）
4. **会后用存档 wav 全量重跑**：wav 是完整实时的，质量比实时切片更高

### A2. 静音段凭空编内容（幻觉）

实时转写最大的敌人不是"听不清"，而是模型在静音时编内容。典型：

- `Thank you for watching!`
- `Subtitles by the Amara.org community`
- `Please subscribe`
- `AI, AI, AI, AI, AI` ／ `R&D, R&D, R&D` ／ `Models, Models`（逐字重复型）

四重保险已内建在 `live_capture.py`：**有效语音时长闸门**（检出语音 < 0.8 秒直接丢弃，最关键）、
**静音闸门**（音量低于阈值不送模型）、**弱特征黑名单**（短句才丢，不误伤正常发言）、
**强特征黑名单**（命中即丢）。中英双语都覆盖，回归测试零误判。
过滤片段只在控制台提示，**不写进转写文件**。

> 整理摘要时**还要再过滤一遍**：这些噪声会残留在转写里（见 `02-会中整理规则.md` 第 3 步）。

### A3. 转写跟不上（越录越落后）

| 切片 | 实测吞吐 |
|---|---|
| **10 秒** | **0.51x 实时 → 追不上** |
| 20 秒 | 1.29x |
| 30 秒 | 0.91x（受并发干扰，偏保守） |
| **整段不切** | **2.40x** |

原因：**Whisper 编码器固定按 30 秒窗口计算**，切片越短，这份固定开销摊在越少音频上，单位代价越高。
再叠加 `beam=1`（贪心解码，约快 2 倍，且噪声段不再陷入重复幻觉的长解码）。

**结论：`--chunk 20 --beam 1` ≈ 2.5x 实时。不要为了"低延迟"把切片调小。**

诊断工具：`lag_check.py`（只读时间戳，不加载模型、不占 CPU）。
补救：茶歇停掉重启，或会后用 wav 重跑。

### A4. 录成静音 / 录不到声

- 检查是否有**虚拟麦克风**（EaseUS VoiceWave 等）被设为默认输入 —— 实测其拾音电平 0.00001，完全死
- 用 `麦克风实测.cmd` → `[2]` 扫一遍，比对各设备电平
- ⚠️ **别用"扬声器外放"来测远场**：会触发 Windows **AEC 回声消除**（主动消除本机扬声器的声音），
  这是设计行为不是故障，**不能用来推断真人讲话效果**

### A5. 中途崩溃 / 分多轮

采集崩了重启会开**新的一轮**并自动把上一轮转写归档为 `live_transcript_<开始时刻>.txt`。
所以多轮是常态 —— 会后用 `merge_transcripts.py` 合并即可。
**归档文件命名 = 该轮采集的开始时间**，可据此定位任意时段原文。

## B. 看板（HTML）

### B1. 页面整片空白 ★最常见

根因几乎都是**模板占位符被污染**：

- `@@CONTENT@@` / `@@LIVEFEED@@` 在模板里出现**多于一次**（尤其别在 JS 或注释里写出这串字面量）
  → 整块 markdown 被塞进 JS，字符串字面量被换行截断 → `<script>` 语法错误 → 内容区永远空白，
  而"占位符已替换"之类的检查**全都通过**，看不出问题
- 注入内容里出现 `</script>` → 提前截断脚本块（脚本已自动转义为 `<\/`）

**唯一可靠的验收方式**：`check_board.js` —— 用 Node 桩出 DOM **真实执行**看板脚本，
验证"页面真能显示"。别只看占位符计数。

`build_board.py` 已内建三道自检（占位符计数 / script 标签数量 / JS `node --check`），
失败时**拒绝写入**，原 HTML 保持不动。看到 `[构建失败]` 就按提示修，**不要手写 HTML 绕过**。

### B2. 摘要更新了但看板没变

`build_board.py` **必须是流程的最后一步**。若之后又改了 `会议摘要-双语.md`，**再跑一次**。

### B3. 看板刷新守护起不来

`_watch.lock` 存 PID 做单实例锁。若残留但进程已不在，会自动接管；
若确实重复双击，会提示"已有实例在运行"，关掉新窗口即可。

### B4. 实时原声层不动

需要先双击 `启动看板刷新.cmd`。它**只读** `live_transcript.txt`、**只写** `会议看板.html`，
不碰录音、不占 CPU（约 1%）。关掉它不影响录音。

## C. 整理与自动化

### C1. 「自动更新摘要」不可靠

定时任务的**最小粒度是 1 小时**，且实测带 5–10 分钟随机抖动
（首次触发落在 09:27 而不是 09:20）。

**"实时"由本地循环的「实时原声层」承担**（无模型、无调度器、不会失约）；
摘要层要最新，最快仍是在对话里说一句「**更新摘要**」。

### C2. 同一任务被并发触发

症状：两个整理实例同时在写 `会议摘要-双语.md`，内容互相覆盖。

**开工前必查**：
1. `会议摘要-双语.md` 的 mtime 是否仍在变动（有人在写）
2. `_note_state.json` 的 `covered_until` 是否已比记忆中的更新

若已有实例把 `covered_until` 推到较新位置 → **以该位置为起点续写增量**，
不要按"整文件皆新增"重做，否则会重复写入。

### C3. 摘要被外部回退 ★最阴的坑

实战中 `会议摘要-双语.md` 曾被**回退到 90 分钟前的旧版本**，
此前写入的内容全部消失，同时旧的格式红线违规写法重新出现。
排查：目录内没有任何进程会写该文件 → 推测为同步盘/备份软件回退。

**快速判据**：比对「`_note_state.json` 的 `covered_until`」vs「摘要正文实际写到的最后时间戳」。
**只要摘要落后于 `covered_until`，就必须补齐缺口**，否则 `covered_until` 一旦推进，
缺失区间将**永久不被整理**。

**给用户的话术**：发现缺口后要明确告知"XX 时段内容未落入摘要"，不要当成无事发生。

### C4. 格式红线违规混入

`6\.`、`R\&D`、`\_`、`&#x52;`、`&amp;` 这类写法会在看板里原样显示成怪符号。
发现后可以正则批量清理：

```python
t = re.sub(r"&#x[0-9A-Fa-f]+;", lambda m: chr(int(m.group(0)[3:-1], 16)), t)  # HTML 实体还原
t = re.sub(r"\\([.\-_&*|`])", r"\1", t)                                        # 去掉多余反斜杠
```

## D. 本机环境注意（Windows + WorkBuddy）

- **Python 解释器不再写死**：`init_project.py` 用 `sys.executable` 生成 `.cmd`，
  换机器不需要改任何路径（2026-10-21 修正）。若沿用旧目录，`.cmd` 里的 `set PY=` 仍是老的，重跑一次 `init_project.py --refresh`。
- **模型与 node 都是「能找到就用，找不到降级」**：模型缺失只提醒（首录自动下载）；
  node 缺失只跳过 JS 语法校验，不影响出看板。真正卡住的只有缺少依赖包 → 跑 `preflight.py`。
- **`.cmd` 文件里不要写中文**：cmd.exe 按 GBK 解析 .cmd，中文会导致"行被拆断、命令解析失败"。
  所以所有 `.cmd` 只保留纯 ASCII 调用逻辑，中文交互全部放在 `launcher.py` 里。
- **Python 脚本打印 emoji/CJK 符号会抛 `UnicodeEncodeError: 'gbk' codec ...`**：
  脚本开头必须 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`（stderr 同样），
  父脚本用 subprocess 串子脚本时还要给子进程传 `env` 里的 `PYTHONIOENCODING=utf-8`。
- **多步落盘脚本的验收必须清点全部产物**，不能只看退出码或第一个文件在不在 ——
  子进程编码报错会让父脚本短路，出现"前面的产物已落盘、后面的步骤静默没跑"这种最阴的失败态。
- **网盘 / 同步盘里 `os.replace` 可能报 PermissionError**（目标文件被同步进程占着，改名语义被拒，覆盖写不会）。
  落盘一律用「写 .tmp → 复制覆盖」：`Copy-Item -LiteralPath $tmp -Destination $final -Force`。
- **PowerPoint COM 打开网盘 pptx 视同步状态而定**：写脚本时做成兜底式 ——
  先直开，`except` 时再 `copy2` 到本地临时目录重开。**用副本做量测，绝不在原文件上 Save**。
- 中文路径一律用 `-LiteralPath`，不要用 `-Path`。

## E. 体检清单（开工前 60 秒）

```
<python> preflight.py          # 依赖 / 模型 / node / 麦克风 / 磁盘 / 工作目录
<python> new_session.py --check  # 模板 / 引擎 / 启动器 / 模型 / node / 残留标记
```

`preflight.py` 面向「这台机器能不能跑」，会直接给修复命令（`--fix` 自动装 Python 依赖）；
`new_session.py --check` 面向「这个工作目录是否铺好」，缺文件才报错，模型与 node 只提醒。

## F. 2026-10-21 通用化改造时发现并修掉的问题

| 问题 | 症状 | 根因 | 修法 |
|---|---|---|---|
| **中文会议会被整场清空** | 会后 `_topics` 里中文条目全没了 | `split_topics.is_junk` 按 `[A-Za-z&']+` 数词元，中文词元数 = 0 → 一律判垃圾 | 中文行改为按汉字数判定（≥2 保留）；英文规则只作用于剩下部分 |
| **中文重复段去不掉** | 同一段话被转两次，合并后仍在 | `merge/dedup` 的 `norm()` 只留 `[a-z0-9]`，中文被抹成空串 → 长度 0，永远跳过比较 | `norm()` 保留汉字；去重阈值与 shingle 对中文单独取值 |
| **误双击两次 → 转写交错** | 同一行内容重复出现、时间戳乱序 | 采集端没有单实例保护（只有看板守护有锁） | 新增 `_capture.lock` + PID 存活判断，重复启动直接拒绝 |
| **网盘上开场归档失败** | 启动即报错，或上一场内容与本次混在一起 | 归档用 `os.replace`（rename 语义），网盘拒绝 | 失败时退化为「复制 + 清空」，并在控制台说明 |
| **落后了没人知道** | 录到后面越来越慢，结束时才发现缺了一半 | 队列无上限、无异状提示 | 积压 ≥6 段时打印「落后约 N 秒」，不丢音频但让人当场看见 |
| **无议程的会跑不动** | `sessions` 为空 → 一个议题切片都没有，全部落进 GAP | 数据模型要求先有议程 | 空 sessions 自动进入**单场模式**（T1 覆盖全程） |
| **中文/自动模式追不上** | 1 小时的会要转 2 小时 | 菜单里 zh/auto 用 `beam=5`，约 0.5x 实时 | 降到 `beam=2`；英文仍用 `beam=1` |
