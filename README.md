# live-meeting-notes

**本地离线会议记录技能** —— 现场录音、实时看板、会后逐议题双语纪要，音频不出本机。
适用于 Claude Code / WorkBuddy 等支持 skill 的智能体，也可当独立命令行工具使用。

```bash
git clone https://github.com/KHWD0922/live-meeting-notes.git
cd live-meeting-notes
python -m pip install -r requirements.txt
python scripts/init_project.py "D:\Meetings\2026-11-05 客户大会"
cd "D:\Meetings\2026-11-05 客户大会"
python preflight.py        # 体检：依赖/模型/node/麦克风/磁盘
```

> 首次运行会下载约 460MB 的 Whisper small 模型（国内走 hf-mirror 镜像）。

---

## 详细介绍与使用说明

> 一句话：把一台普通笔记本变成**本地会议记录工作台** —— 现场录音、实时中英文字幕看板、会后逐议题双语纪要，**音频全程不出本机**。
>
> 适用于：会议 / 研讨会 seminar / 座谈会 panel / 培训 / 线上会
> 版本：v1.1.1（2026-10-21，公开发布版）｜ 单人操作 ｜ 无需管理员权限

## 0. 先建立正确预期（这一节比后面都重要）

**它是三样东西的组合，不是一个 App：**

1. **一个本地转写引擎** —— faster-whisper，在你的 CPU 上跑，音频不上传；
2. **一套 AI 整理规则** —— 把转写变成双语要点、行动项、逐议题纪要；
3. **一个实时看板** —— 浏览器里看，15 秒刷新一次。

**它不是什么（这几点最容易被误解）：**

| 常见误解 | 实际情况 |
|---|---|
| "打开就能录" | 需要先装 Python 依赖、铺一次会议目录；之后每场会只需 10 分钟准备 |
| "全自动出纪要" | 摘要那一步需要 AI（WorkBuddy 或其它大模型）按规则整理；纯脚本只出转写 |
| "会议软件插件" | 不接 Zoom / Teams / 腾讯会议，靠**麦克风拾音**（线上会就开外放） |
| "能分清谁在说" | **不做说话人分离**。多人讨论会混成一条流，靠上下文判断 |
| "能记下公式和图表" | 语音识别对公式、符号、图表描述基本无能为力，这类内容仍要拍幻灯片 |

> 一句话总结：**转写可靠、看板实时、纪要靠 AI、说话人靠人。**

## 1. 它解决什么问题

| 现场痛点 | 这套流程怎么做 | 你得到什么 |
|---|---|---|
| 会开完只记得三句话 | 全程转写，每 20 秒一行带时间戳 | 可检索的逐字稿，忘了就回去查 |
| 双语会议听不全、记不快 | 会中 AI 写中英对照摘要 | 10 分钟读完一场会的主线 |
| 会后写纪要要两小时 | 四步脚本切片，AI 逐议题写 | 20 分钟出可交付文档 |
| 录音不敢传云端 | 本地推理，音频不出机器 | 数据可控（但摘要文本会进模型，见第 9 节） |
| 议题多、材料散 | 按议程时间窗自动切片 | 一议题一份材料，目录清晰 |
| 会中临时被问"刚才说到哪" | 看板顶部实时原声 + 议程进度条 | 抬眼就能答 |

## 2. 适用场景

| 场景 | 典型用法 | 配置要点 |
|---|---|---|
| **内部会议 / 项目会**（1 小时内） | 无议程直接录，会中看板、会后一份纪要 | `sessions: []` 单场模式 |
| **研讨会 / seminar**（半天，多讲者） | 按议程分段，会后一议题一章 | 填 `sessions` 起止时间与讲者 |
| **座谈会 / panel** | 单场或按嘉宾发言段切分 | 无法区分说话人，摘要里用"有嘉宾提出…"表述 |
| **培训 / 工作坊** | 长时段录制，重点在会后 | 注意"30 分钟静默即判定散会"的规则（见 FAQ 4） |
| **线上会**（Zoom / Teams / 腾讯会议） | 开外放，用麦克风拾音 | 戴耳机时麦克风收不到对方声音，需外放或虚拟声卡 |
| **客户拜访 / 访谈** | 单场录制 + 会后整理 | 必须先取得对方同意（见第 9 节） |

**不适合的场景（请提前避开）：**

- 需要**逐字归属到人**的圆桌、访谈、庭审式记录；
- 强噪声环境（展会现场、开放工位旁）；
- 需要把字幕**实时投到大屏**给全场看（看板可投，但没有专门的字幕模式）；
- 以公式推导、图表讲解为主的技术课（转写会丢掉核心内容）；
- 只有手机、没有电脑的场合。

## 3. 适用对象

**适合：**

- 需要**一手记录**、又要求材料可交付的人：咨询顾问、售前、项目经理、研究员、媒体、法务合规；
- 经常参加**英文为主、母语中文**的会议，需要"英文可核对 + 中文可速读"；
- 对数据外传敏感，倾向本地处理；
- 愿意在会前花 10 分钟做准备的**单人操作者**。

**不太适合：**

- 期待"零配置、点开就用"的人；
- 需要多人同时在一台机器上各记各的；
- 需要"谁说的"作为刚需的场景（当前版本做不到）。

## 4. 硬件与软件环境

### 4.1 配置要求

| 项目 | 最低 | 推荐 | 说明 |
|---|---|---|---|
| 操作系统 | Windows 10/11 64 位 | 同左 | macOS / Linux 可运行（启动器为 `.sh`），但未做充分实测 |
| CPU | 4 核 | 近三年 6 核以上 | **转写只吃 CPU，不调用显卡**。CPU 决定能不能跟上说话速度 |
| 内存 | 8 GB | 16 GB | 模型常驻约 1 GB |
| 磁盘 | 5 GB 空闲 | 20 GB 以上 | 模型 460 MB；录音约 **115 MB/小时** |
| 麦克风 | 笔记本内置 | USB 全向会议麦 / 领夹麦 | **音质收益最大的一笔投入**，比换大模型管用 |
| 网络 | 仅首次需要 | — | 首次下载模型约 460 MB（国内走 hf-mirror 镜像）；**会中完全离线** |
| 权限 | 普通用户 | — | 不需要管理员权限 |

### 4.2 软件依赖

- **Python 3.9+**（必需）
- Python 包：`numpy` `sounddevice` `faster-whisper` `zhconv`（必需，一条命令装完）
- **Node.js 18+**（可选）：只用于看板生成后的 JS 语法自检，没有也能出看板
- **ffmpeg**（可选）：只用于音频格式转换 / 分析旧录音

### 4.3 实测速度（重要）

| 场景 | 处理速度 | 结论 |
|---|---|---|
| 英文，切片 20 秒 + 贪心解码 | 约 1.3–2.5 倍实时 | 一台会议机可稳定跟上 |
| 中文 / 中英自动检测 | 明显更慢 | 轻薄本可能接近或低于 1 倍 → 会持续落后 |

- 落后时控制台会打印「**落后约 N 秒**」，不会悄悄丢内容，但会越拖越久。
- **省电模式会大幅降频**，务必接电源、电源计划设为「高性能」。
- 显卡再好也用不上（当前固定 CPU 推理），不要指望它加速。

## 5. 安装

有两种用法，按你的情况选一种。

### 路径 A：作为 WorkBuddy 技能（推荐，能用上 AI 整理）

1. 把 `live-meeting-notes-v1.1.1.zip` 解压到：
   `C:\Users\<你>\.workbuddy\skills\`（解压后应得到 `live-meeting-notes\SKILL.md`）
2. 装依赖（只需一次）：
   ```
   python -m pip install -r .workbuddy\skills\live-meeting-notes\requirements.txt
   ```
3. 新开一个会话，技能即生效。之后直接用自然语言触发：
   - 「帮我为下周的客户大会搭好录音整理环境，目录 `D:\Meetings\2026-11-05`」
   - 「更新摘要」
   - 「把这批转写整理成会后纪要」

### 路径 B：独立使用（不依赖 WorkBuddy）

1. 解压到任意目录（如 `D:\Tools\live-meeting-notes`）；
2. 装依赖：`python -m pip install -r requirements.txt`；
3. 铺一个会议目录：
   ```
   python scripts\init_project.py "D:\Meetings\2026-11-05 客户大会"
   ```
4. 体检：`python preflight.py`（在会议目录里跑）。

> 路径 B 能完整跑「录音 → 转写 → 看板 → 切片 → 装订」，**唯独第 4 步"逐议题写摘要"需要 AI**：
> 可以把 `references\02-会中整理规则.md` 交给任意大模型执行。

### 安装后必须做的一次校验

```
python preflight.py
```

它会逐项检查 Python / 依赖包 / 模型 / node / 麦克风 / 磁盘，缺什么直接给修复命令；
加 `--fix` 可自动安装缺失的 Python 依赖。**看到"可以开录"再往下走。**

## 6. 使用流程

### 6.1 会前 10 分钟

| 步骤 | 做什么 | 为什么 |
|---|---|---|
| 1 | 铺目录：`init_project.py "<会议目录>"` | 一次性；之后每场会可以复用同一目录（新会议建议新建） |
| 2 | 填 `术语表.txt`：人名、公司名、产品名 | **必做**。实测 `Kubernetes` 不加表会转成 `Cooper Netes` |
| 3 | 填 `议程配置.json`（可选） | 有议程就分段；**没有就保持 `sessions: []`**，整场按一个议题处理 |
| 4 | 双击「环境体检」 | 确认模型、麦克风、磁盘都正常 |
| 5 | 双击「麦克风实测」→ 选 2 | 挑电平最高的设备；虚拟麦克风常导致录成静音 |

**摆位（决定成败）：** 笔记本正对讲台，屏幕打开 100–110°，别挡住屏幕上边框的麦克风阵列；机器下垫一本薄书减震；避开空调出风口。

### 6.2 会中 3 个动作

1. 双击「**启动实时转写**」→ 选语言（英语为主 / 中英混合 / 中文为主）；
2. 双击「**启动看板刷新**」，浏览器打开 `会议看板.html` 放到一个标签页；
3. 关键节点**打锚点**（记下 `HH:MM:SS` 与一句摘要），会后切片定位会快很多。

需要刷新摘要时，对 WorkBuddy 说「**更新摘要**」，或在对话里让它按 `references\02-会中整理规则.md` 执行。

### 6.3 会后（20 分钟）

```
merge_transcripts.py    # 合并多轮转写 + 时间窗去重 + 按议题切片
dedup_global.py         # 全局近似去重（附每分钟密度报告，可查漏录）
split_topics.py         # 精修后重新切片（过滤噪声行）
（AI）写 _summary\S*.md 与 _record\T*.md   # 唯一没有脚本的一步
build_delivery.py       # 装订成 会后交付.md / .html（自带表格校验）
（可选）导出 Word
```

## 7. 输出结果

### 7.1 会中就能看到

| 文件 | 内容 | 使用者 |
|---|---|---|
| `会议看板.html` | 上层：AI 写的中英摘要（按议题分段）；下层：最近 120 行实时原声；顶部：议程进度与当前时段 | 你自己，随时抬眼看 |

### 7.2 会后交付

| 文件 | 内容 | 给谁 |
|---|---|---|
| `会后交付.html` | **主交付物**。独立单文件、可离线打开、可打印；每议题先 Summary（1 页速读）再逐段双语记录 | 客户 / 上级 / 同事 |
| `会后交付.md` | 同上，Markdown 版，便于再编辑 | 你自己 |
| `会议摘要-双语.md` | 会中持续维护的双语摘要（一页摘要 / 议题要点 / 关键原话 / 行动项 / 存疑） | 你自己 |
| `全文转写-最终.txt` | 去重排序后的完整逐字稿（带时间戳） | 检索底稿 |
| `_topics\T*.txt` | 按议程切好的分议题素材 | 写摘要的输入 |
| `_summary\S*.md` | 每议题 1 页 Meeting Summary | 装订用 |
| `_record\T*.md` | 每议题的双语逐段记录 | 装订用 |
| `recording_*.wav` | 原始录音（16 kHz 单声道，约 115 MB/小时） | 复听 / 重转 |
| `_note_state.json` | 整理进度指针（**不要手改**） | 程序用 |

> 交付物长什么样：一份带目录、按议题分章、每章"先摘要后原文"的双语文档，表格与引用可直接打印。
> Word 版需要额外一步转换，不属于默认产出。

## 8. 质量由什么决定（按影响力排序）

1. **麦克风位置与音源** —— 近场、正对、无遮挡，比任何参数都重要；
2. **术语表** —— 人名、公司名、产品名不填，错得最离谱；
3. **模型大小** —— 默认 small（CPU 友好）；准确率优先可换 medium，但会明显变慢；
4. **切片与解码参数** —— 20 秒 + 贪心解码是"跟得上"的默认值，改小会追不上。

**准确率预期：** 安静室内、近场、标准口音 → 可用于交付（仍需通读校对）；远场、口音重、术语密集 → 必须靠术语表 + 会后人工校对。
**永远不要跳过校对**：AI 整理只做归纳，不负责纠正听错的内容。

## 9. 合规与隐私（务必先读）

- **录制前取得同意**：现场会议需征得主办方/讲者同意；客户场合建议在开场说明。
- **音频与转写留在本机**：不上传云端，这是本方案的核心设计。
- **但摘要那一步不是离线的**：转写文本会进入大模型（如 WorkBuddy）才能生成摘要。
  对外表述请准确说「**音频不出本机**」，不要说「全程离线」。
- **涉密/敏感会议**：只用转写与本地看板，不启用 AI 摘要；或改接本地部署模型。
- 记录内容可能含个人信息与商业机密，分享前请确认接收方与范围。

## 10. 常见问题

**1. 双击启动器一闪而过？**
多为 Python 路径或依赖问题。在会议目录里跑 `python preflight.py`，按提示修；`.cmd` 里可以改 `set PY=` 指向你的 python.exe。

**2. 看板一片空白？**
两种情况：① 摘要文件被写坏（用 `build_board.py` 看报错，它会拒绝写入并说明原因）；② 模板占位符被污染（重新 `init_project.py --refresh` 铺一份模板）。

**3. 转写越来越慢 / 落后几百秒？**
切片太小或机器太慢。保持 `--chunk 20 --beam 1`（中文用 `--beam 2`）；接电源、关省电模式；关掉其它吃 CPU 的程序。

**4. 会中摘要停了？**
整理流程有"**30 分钟无新转写即判定散会**"的保护。长时间静默（写代码、分组讨论）会触发，属于预期行为；需要的话手动说「更新摘要」。

**5. 提示"已有进程在跑"？**
防双开的单实例锁。先双击「停止转写」；确认没有进程后，删除会议目录里的 `_capture.lock` 再启动。

**6. 多人讨论分不清谁说的？**
当前版本没有说话人分离。缓解办法：主持人点名（"请张总说一下"）、会后按议题归纳而非按人归纳。

**7. 线上会对方的声音录不到？**
麦克风只收环境声。需要外放扬声器，或自行配置"虚拟声卡/立体声混音"把系统声音当输入源。

**8. 能直接出 Word 吗？**
`build_delivery.py` 出 Markdown 与 HTML；Word 需要额外转换一步，不是默认产出。

```
【会前】
  1. init_project.py "<会议目录>"        ← 每场会一次

【三条铁律】
  · 录音前取得同意
  · 音频不出本机，但摘要文本会进模型
  · 交付前必须人工通读校对
```
